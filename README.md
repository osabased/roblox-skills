# Roblox Skills

Focused decision, review, and Roblox-development skills that supplement planning, implementation, and code-review workflows. Use the narrowest owner for the live problem; each skill returns control after its bounded task.

## Choose by problem

| Situation | Skill | Owns |
| --- | --- | --- |
| Materially different consequential directions remain competitive | [**direction-selection**](./direction-selection/) | Comparative evidence, direction choice, and a commitment-scoped gate |
| A consequential subjective choice is unresolved | [**subjective-taste-alignment**](./subjective-taste-alignment/) | Applicable taste, current intent, and preference-sensitive propagation |
| A defined system may fail across components or operational conditions | [**system-review**](./system-review/) | Cross-component scenarios, system defects, visibility gaps, and root-cause diagnosis |
| Roblox DataModel placement, runtime ownership, entrypoints, source-of-truth workflow, or organization is in scope | [**structure-roblox-projects**](./structure-roblox-projects/) | Roblox project structure and authorized structural change |
| A Roblox community resource must be found, qualified, adopted, refreshed, or repaired | [**roblox-resource-acquisition**](./roblox-resource-acquisition/) | Resource evidence, trust, verification, integration, and lifecycle state |

## When concerns overlap

- Let the domain owner establish facts or preferences first. Use `direction-selection` only when materially different directions still require comparison.
- `system-review` diagnoses system defects. When more than one consequential correction remains credible, it hands the decision to `direction-selection`.
- `structure-roblox-projects` owns Roblox organization. `system-review` joins only when that structure participates in a cross-component failure.
