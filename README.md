## Skill catalogue

Use the narrowest skill that owns the current problem.

| Problem | Owning skill |
|---|---|
| Materially different consequential directions remain competitive | [**direction-selection**](./direction-selection/) |
| A consequential subjective choice is unresolved | [**subjective-taste-alignment**](./subjective-taste-alignment/) |
| A defined system may fail across components or operational conditions | [**system-review**](./system-review/) |
| Roblox DataModel placement, runtime ownership, entrypoints, grouping, or source-of-truth workflow | [**structure-roblox-projects**](./structure-roblox-projects/) |
| A Roblox community resource must be found, qualified, adopted, refreshed, or repaired | [**roblox-resource-acquisition**](./roblox-resource-acquisition/) |

## Ownership rules

- Let the domain owner establish facts or preferences before using `direction-selection` to compare materially different surviving directions.
- `system-review` owns diagnosis of defined cross-component behavior. When one demonstrated defect has multiple materially different consequential corrections, it preserves the diagnosis and hands the replacement decision to `direction-selection`.
- `structure-roblox-projects` owns Roblox organization unless that organization participates in a broader cross-component failure.
- Local implementation review stays with the applicable code-review workflow rather than `system-review`.
